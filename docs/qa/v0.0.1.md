# QA notes: Linka Backend 0.0.1

Runbook проверяет реальный flow 0.0.1: папка → набор → три файла → удаление двух файлов → новый файл → версия и откат → `.linka`-архив → два ученика → общая библиотека → удаление данных.

Команды рассчитаны на Bash, `curl`, `jq`, `python3`, Go и запущенный Docker. Выполнять их нужно из корня `zip-backend`.

## 1. Автономный E2E — обязательная проверка

Тесты сами запускают PostgreSQL, Redis и MinIO через Testcontainers, применяют реальные миграции и вызывают HTTP handlers:

```bash
go test -tags=e2e ./e2e ./internal/picturebank \
  -run '^TestE2E_' -race -count=1 -v
```

Ожидаемый результат: все тесты `PASS`. В частности:

- `TestE2E_RealPackLifecycle` проверяет файлы, защиту используемого медиа, архив, версии, откат, двух учеников, библиотеку и полную очистку;
- `TestE2E_P1UserJourney` проверяет права, папки, приватность и публикацию;
- `TestE2E_RefreshTokenLifecycle` проверяет rotation, replay и отзыв token family;
- `TestE2E_PicturesBankImportAndArchive` проверяет внешний контракт через локальный stub, импорт картинки и попадание картинки в архив.

Полный regression перед релизом:

```bash
go test ./... -race -count=1
golangci-lint run ./...
go build ./cmd/...
```

## 2. Запуск настоящего сервиса

```bash
make run-local
```

Цель поднимает `postgres`, `minio`, `nats`, `redis`, применяет миграции и стартует сервер с `FEATURE_LOCAL_BANK=false`.

`make run-local` остаётся работать в отдельном терминале. API слушает `8080`, health endpoints — `9090`, MinIO console — `9001`.

```bash
curl --fail --silent --show-error http://localhost:9090/livez | jq
curl --fail --silent --show-error http://localhost:9090/readyz | jq
```

Оба запроса должны вернуть HTTP 200. В `/readyz` проверка `minio` — это объектное хранилище медиа и архивов, а источник картинок виден отдельно: `pictures_bank.detail = "external https://pictures.linka.su"` (внешний банк не пингуется, чтобы готовность сервиса не зависела от стороннего сервиса). Для 0.0.1 используется внешний Pictures Bank. При `FEATURE_LOCAL_BANK=true` сервер ожидаемо завершится с `local pictures bank is not implemented`.

## 3. Авторизация

Публичной регистрации в 0.0.1 нет. Для ручной проверки нужны заранее созданные учётные записи автора с ролью `defectologist` и читателя. Читатель нужен только для проверки опубликованного набора.

```bash
export BASE_URL=http://localhost:8080
export QA_EMAIL='author@example.com'
export QA_PASSWORD='replace-me'
export QA_READER_EMAIL='reader@example.com'
export QA_READER_PASSWORD='replace-me'
export QA_DIR=/tmp/linka-qa-0.0.1
mkdir -p "$QA_DIR"

LOGIN_RESPONSE=$(curl --fail --silent --show-error \
  --cookie-jar "$QA_DIR/author.cookies" \
  --header 'Content-Type: application/json' \
  --data "$(jq -nc --arg email "$QA_EMAIL" --arg password "$QA_PASSWORD" \
    '{email:$email,password:$password}')" \
  "$BASE_URL/api/v1/auth/login")
export ACCESS_TOKEN=$(jq -er '.access_token' <<<"$LOGIN_RESPONSE")

READER_LOGIN_RESPONSE=$(curl --fail --silent --show-error \
  --cookie-jar "$QA_DIR/reader.cookies" \
  --header 'Content-Type: application/json' \
  --data "$(jq -nc --arg email "$QA_READER_EMAIL" --arg password "$QA_READER_PASSWORD" \

  "$BASE_URL/api/v1/auth/login")
export READER_ACCESS_TOKEN=$(jq -er '.access_token' <<<"$READER_LOGIN_RESPONSE")
```

Ожидание: оба ответа содержат `access_token`, cookie jars — HttpOnly cookie `refresh_token`. Секреты и токены не коммитить.

## 12. Refresh rotation и replay

Проверять в самом конце: повторное использование старой cookie отзывает всю её token family.

```bash
curl --fail --silent --show-error \
  --cookie-jar "$QA_DIR/rotation.cookies" \
  --header 'Content-Type: application/json' \
  --data "$(jq -nc --arg email "$QA_EMAIL" --arg password "$QA_PASSWORD" \
    '{email:$email,password:$password}')" \
  "$BASE_URL/api/v1/auth/login" >/dev/null
cp "$QA_DIR/rotation.cookies" "$QA_DIR/old-refresh.cookies"

curl --fail --silent --show-error \
  --request POST \
  --cookie "$QA_DIR/rotation.cookies" \
  --cookie-jar "$QA_DIR/rotation.cookies" \
  "$BASE_URL/api/v1/auth/refresh" | jq -e '.access_token | length > 0'

test "$(curl --silent --show-error --output /dev/null --write-out '%{http_code}' \
  --request POST --cookie "$QA_DIR/old-refresh.cookies" \
  "$BASE_URL/api/v1/auth/refresh")" = 401

test "$(curl --silent --show-error --output /dev/null --write-out '%{http_code}' \
  --request POST --cookie "$QA_DIR/rotation.cookies" \
  "$BASE_URL/api/v1/auth/refresh")" = 401
```

Ожидание: первый refresh меняет cookie; replay старой cookie возвращает 401; новая cookie этой семьи после replay тоже возвращает 401.

## 13. Rate limit

Запускать последним, чтобы лимит не мешал основному flow. В dev-конфигурации login допускает пять запросов в минуту с одного IP:

```bash
for attempt in 1 2 3 4 5 6; do
  curl --silent --show-error --output /dev/null \
    --write-out "attempt=$attempt status=%{http_code} retry-after=%{header.retry-after}\n" \
    --header 'Content-Type: application/json' \
    --data '{"email":"nobody@example.com","password":"wrong-password"}' \
    "$BASE_URL/api/v1/auth/login"
done
```

Ожидание: не позднее шестого запроса приходит 429 и непустой `Retry-After`. Счётчик мог быть частично израсходован предыдущими login-запросами.

## Критерий приёмки 0.0.1

- Regression, build и автономные E2E зелёные.
- `/readyz` возвращает 200 со всеми готовыми зависимостями.
- Ручной flow проходит без неожиданных 4xx/5xx.
- Запрещённые операции возвращают ожидаемые 401, 404, 409 или 429.
- После очистки набор недоступен, папки удаляются, media objects больше не заняты.
- Сбой внешнего Pictures Bank изолирован до 503 и не ломает остальной API.
